1) How would you optimize queries when tables grow from thousands to billions of records?
        
        When tables grow from thousands to billions of rows, 
        I focus on 

	        Avoid SELECT *
	        Filter early (predicate pushdown)
            Join on indexed columns 
            partitioning the large table
            analyzing execution plans using EXPLAIN 


2) How do you identify a slow query?

	*) I identify queries with high execution time,
	*) Analyzing execution plans using EXPLAIN  to understand where the query is spending most of its time
	*) I look for 
	        Avoid SELECT *
	        Filter early (predicate pushdown)
            Join on indexed columns 
            partitioning the large table

            
2) what is query plan analysis ?

    To understand how a query is executed
    By using explain identify expensive operations like inefficient joins, full table scans , large sorts, and missing index usage 
    we optimize the query through indexing, partitioning, query rewrites, statistics updates, or join strategy improvements
    Query plan analysis is one of the most effective techniques for diagnosing and resolving SQL performance issues
