1) What is difference between clustered and non-clustered index?

Clustered Index :
        *) It Store Physically data on disk and sorts the data in the table
        *) It doesn't require extra storage for data (data itself is in index)
        *) Only One per table
        *) Frequently used for primary key 
        *) It is suit for Range queries (BETWEEN) and Sorting queries (ORDER BY)

Non-Clustered Index :
        *) It doesn't stored data in index order
        *) It require Separate data structure from table then the stores indexed column values along with row
        *) Multiple allowed table
        *) Frequently used for foreign keys
        *) It suit for filtering queries , search queries and  join queries


2) Can a table have multiple clustered indexes?
        No ,  a table cannot have multiple clustered indexes.


3) What is index scan vs index seek ?

        Index Seek (Efficient)     :
                It will find the matching rows by directly reading the specfic index
                
                Ex :
                Works like reading the table of contents in a book.
                
        
        Index Scan (Less Efficient) :
                It will find the matching rows by reading all of the index pages 

                Ex :
                Works like reading the entire table of contents page by page


4) What is B-Tree index?
        It is a type of index structure 
        It is used by most databases.
        It organizes the data in a tree structure, which allows the database to quickly find 
rows without scanning the entire table.


5) What is cardinality?
        It refers to the number of distinct values in a column


6) What happens when you index low-cardinality column ?
        It may not improve performance
        sometimes can even hurt performance


7) Why Indexing Low-Cardinality Columns Can Be Inefficient ?
        Such columns have few distinct values, so many rows match the same value. 
This leads to poor selectivity .

        queries may still need to scan a large portion of the table
making the index less effective


8) When should you not use index?
        When the table is small
        the column has low cardinality, 
        the column is frequently updated, 
        the queries are not selective and return most rows
        Indexes improve read performance but add storage overhead and slow down write operations


9) What is index fragmentation?
        logical order of index pages does not match the physical order of data pages on disk, 
causing inefficient reads.  
        Fragmentation slows down SELECT queries and increases I/O. 
        It can be fixed by reorganizing or rebuilding indexes.


11) Why too many indexes are bad?
        Each write operation (INSERT, UPDATE, DELETE) must update all indexes, 
which slows down performance.
